# V66 旋轉後直行偏擺：2026-11-06 現有資料核對

## 結論及證據界線

已定位到異常發生的環節：旋轉停穩後、四顆被動萬向輪重新轉向時，實際左右驅動輪轉動不一致，且輪子轉動量與車身位移不符合無滑移模型。不是這次路徑規劃或 SLAM 在加入轉向命令。尚不能從這包資料唯一判定「5 N·m 不足」、「某阻尼太大」或「摩擦一定過大」。

降低起步加速度已生效，但不是修復。這次不是最高 0.9 m/s 的通過測試；該前進段命令最高約 0.632 m/s。

## 時間對齊

| 物理時間 | 狀態與證據 |
|---|---|
| 19.617 s | 使用者把旋轉要求改成前進；控制器先輸出零速 |
| 19.8–20.0 s | 車身 yaw 約 63.70°，已停止原先旋轉；不是持續轉彎指令漏進直行 |
| 20.333 s | 前進開始，w=0，四輪滾動軸相對底盤直行軸仍偏約 46.3°、59.0°、52.9°、45.6° |
| 20.333–23.000 s | 萬向輪重新排列，走約 0.364 m，車身 yaw 增加 7.136° |
| 23.000 s | 四顆滾動軸誤差均小於 0.061°；這裡量的是滾動軸方向 modulo 180°，不是保證所有前後拖曳方向相同 |
| 23.000–26.467 s | 繼續約 1.577 m，yaw 只增加 0.0275°，相對這段起始方向橫移約 0.615 mm |

超過 99% 的此段航向改變發生在重新排列期間。這是強時間關聯，不能代替隔離參數的因果驗證。轉彎前基準是倒退、轉彎後是前進，因此亦不是完全匹配的同方向 A/B 實驗。

## 真正的左右差異：使用輪角，不依賴瞬時關節速度

20.333–23.000 s，以 base_link 原始名稱表示：

| 輪子 | 輪角乘半徑的滾動弧長 | 輪心位移投影至各時刻滾動方向 | 兩者差異 |
|---|---:|---:|---:|
| left_drive_wheel_link | −0.39432 m | −0.39350 m | +0.00082 m |
| right_drive_wheel_link | −0.36217 m | −0.33409 m | +0.02808 m |

負號是本次車頭朝 base −X 的正常前進符號。原始 right_drive_wheel_link 是物理車頭座標的左側驅動輪，請勿混用名稱。

輪角差對應 yaw 約 3.862°；車身實際為 7.136°，剩約 3.274° 是無滑移模型差異。原始右驅動輪有約 28 mm 的輪角弧長／輪心滾動位移不一致，明顯大於另一輪約 0.8 mm。這支持滑移／接觸約束誤差的存在，但不是接觸斑滑移率的直接量測。

21.5 s 前約 0.2 s 輪角平均速度為原始左 −1.539、原始右 −1.212 rad/s；左右目標仍相等。不是單一瞬間負輪速讀值的誤判。

23 s 以後兩輪弧長／輪心位移差異都降到約 0.14 mm 的量級。並非輪距錯了就全程持續偏轉的典型表現。

## 設定核對與排除

- 唯一已記錄的接觸對是六輪 collider 與地板，接觸記錄無錯誤、無丟棄；這不保證未觀察區間無碰撞。
- 單一 PhysicsScene，60 Hz，回呼與 manager 時間核對通過。
- 最大傾斜 0.0396°；此次沒有重現先前彈飛。
- 四個 swivel 的 damping 約 0.000349，MaxForce 0.1、stiffness 0、targetVelocity 0；原先前左漏配阻尼問題已不存在。
- 左右驅動輪 damping 都是 100、MaxForce 都是 5、stiffness 0。不能因目標相等就假設實際輪速相等；也沒有隔離的實際馬達扭矩資料足以證明飽和。
- 六輪共用一個 Wheel 材質，static friction 0.7、dynamic friction 0.6。共用材質本身不違法，但目前是未實測的建模假設，不是確認過的實車輪胎特性。
- 低傾斜不等於六輪承載均勻；接觸法向衝量呈不均與轉移，但不能用單筆零衝量宣稱某輪離地。

## 修正方向：先分開接觸模型，保留底層驅動

現有資料不支持盲目加大馬達力矩、增加所有摩擦或再加 PD 補償。優先使用隨附 V66_CasterContactCandidate.py 做一次可還原的接觸材質比較：

- 只將四顆 caster collider 綁定到獨立候選材質 static=0.25、dynamic=0.20、restitution=0。
- 兩顆驅動輪仍保留原材質；不更改 swivel 阻尼、驅動力、幾何、質量、輪距、輪徑、控制、SLAM 或時鐘。
- 候選值是用來檢驗萬向輪接觸阻力敏感性的工程試值，不是廠商規格，也不是已證實修復。降低抓地也可能增加側滑，必須用車身 yaw 及輪角／位移差異一起判讀。
- 地板材質混合規則維持原狀；設定值不等於兩接觸面的實際合成摩擦值。
- 若偏轉下降且輪角／輪心位移一致性改善，支持接觸阻力是重要因素；仍須恢復較高加速度驗證，不能只靠低速通過。
- 若沒有改善或側滑增加，移除候選，下一項才針對驅動響應及六輪剛性共面承載做物理模型處理，不繼續亂調一串參數。

## 使用方式

1. 在 Isaac Sim 按 STOP。保持本次 acceleration=0.1，其他條件先不變。
2. 上傳並在 Script Editor RUN V66_CasterContactCandidate.py；看到 APPLIED。
3. RUN 原 V66_WheelContactCheck.py，再 RUN 原 AMR_V66_Navigation.py，然後 PLAY。
4. 在空曠位置重做一次原本「旋轉 → 前進 → 停止」，保留原停止保護。不要開始建圖或導航，也不要同時套 Smooth patch。
5. 匯出同一組 wheel_contact 與 mapping_session ZIP。檢查面板可能限制手動速度；須在紀錄中比較實際生效的速度，而非只看按鈕文字。
6. 還原：STOP，將本檔尾端 APPLY=True 改成 APPLY=False，再 RUN。只移除本候選層，恢復原綁定。

腳本只修改匿名 Session 子層；不寫 root USD、不覆蓋車體資產，也不發送移動命令。不要 flatten／另存成正式新版以免把未驗證候選固化。離線驗證只確認 USD 綁定、兩顆驅動輪不變與還原；沒有冒充 Isaac Sim 實跑。
