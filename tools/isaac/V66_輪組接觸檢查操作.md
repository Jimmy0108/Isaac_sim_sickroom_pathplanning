# V66 輪組方向與碰撞配對檢查

此程式是診斷 observer，沿用現有導航程式作為唯一馬達控制鏈。不是另一個修復導航版本，不儲存 USD，不調摩擦／阻尼／力矩／質量／幾何／物理步長。

## 執行

1. 上傳 `V66_WheelContactCheck.py` 至目前遠端 `new_car/python_nav/V66_Python_Navigation/`。其 PROJECT 已設定該路徑。
2. 按 Stop，先在 Script Editor 開啟此檔、按 Run。看到 READY 再繼續。它在暫存 layer 對 AGV 剛體加入 ContactReportAPI、threshold=0，訂閱碰撞事件。結束時移除自己的暫存 layer；不更動病房配置。
3. 再開 `AMR_V66_Navigation.py` 按 Run，再按 Play。等原導航程式顯示 Manual ready。
4. 使用 **Wheel direction and contact check** 面板的操作按鈕；此面板會把既有 app 手動速度先限制為 **0.2 m/s**、原地旋轉 **0.3 rad/s**。原導航面板的文字標題可能仍顯示原先 0.9 上限，以診斷面板選定值及輸出的 command 為準。
5. 在原地靜止時先確認 pair events 有增加，沒有 contact errors。若一直零事件，按 Stop simulation/export，取回資料；沒有事件不代表沒有接觸，本程式也不會用「零接觸力」代替未取得的資料。
6. 在有足夠空間的位置，先短程前進、STOP，後退、STOP，左轉、STOP，右轉、STOP。無需要求碰到床／牆或走滿2m。若已出現明顯偏擺或抖動就停止。
7. 低速平順時才能選 0.4、0.6，再到 0.9 m/s。選速度時先停止現有命令，必須再按方向才移動；不自動加速或自動開車。若可用空間不足，就保留未測試標記，不硬做最高速。
8. 按 STOP simulation / export both sessions，等待匯出。若量測傾角超過5°，診斷程式直接結束模擬，避免等待原本20°保護才停止。這是診斷中斷，不是通過停穩驗收。

## 給回哪些資料

- 診斷 ZIP：`V66_Python_Navigation/validation_outputs/wheel_contact_時間碼.zip`。
- 原導航同次 ZIP：`V66_Python_Navigation/slam_outputs/mapping_session_時間碼.zip`。

第一次只需一組資料，不先改一串參數再來回比較。

## 如何判讀

| 觀察 | 可以定位什麼 | 對應修正方向（需資料證實） |
|---|---|---|
| 車輪/底盤碰到床、外部薄物件、重複地板 | collider0/1 真實配對，而非僅由畫面猜 | 修正該外部碰撞形狀或重複幾何，保留有效碰撞 |
| 底盤持續接觸地板，或少數輪負擔集中且接觸衝量暴增 | 結構接觸、支撐與地面問題 | 檢查底盤碰撞外框、輪位／錨點、地板幾何；不是加直行補償 |
| wheel rolling direction 與輪心速度方向不合 | 輪軸朝向或側滑 | 核對 joint axis/localRot；有正確幾何時再比較摩擦與接觸 |
| 萬向輪先呈 leading、迴正後變 trailing，偏擺隨迴正消失 | 起步 caster 翻向是否與偏擺同時發生 | 檢查前後退的初始 caster 朝向與真實拖距，維持被動輪；不單憑旋轉大就鎖死 swivel |
| 接觸點衝量先暴增，再有車身向上速度／傾角 | 接觸衝擊在失穩前出現 | 根據具體 collider 配對檢查穿透、接觸形狀、rest/contact offset |
| 幾何／接觸對象合理，但輪速／高速接觸仍振盪 | 才進入物理數值與 Drive 檢查 | 單獨比較時間步長或 Drive gain，不同時改摩擦、阻尼、質量 |

`wheel_kinematics.json` 記錄所有 link 的世界位姿／速度、所有 DOF 角度／角速度／目標、輪軸方向、輪心的縱向／側向速度，以及平地名義輪底的速度殘差。名義輪底不是實際接觸點，不能單憑此殘差宣稱精確量到滑移率。

萬向輪拖距指標為 `(wheel centre - swivel origin) dot motion_direction`：速度超過0.03m/s且接近平面運動時，負值為輪心拖在 pivot 後方、正值為 leading。低速／離地／大傾角時不應依此判定轉向是否正常。

`contact_pairs.json` 含 actor、collider、事件類型、接觸點、法向、衝量、分離距離、材質與 mesh face index。只接收有本車 actor 的事件；保留最近40,000筆並記錄捨棄數。每組最多保留8個接觸點，但累加所有回報點的衝量大小。AABB 庫存只供廣相檢查，不能當作實際穿透證據。

## 官方參考與限制

ContactReportAPI 與 subscribe_contact_report_events 的使用依據：[Omni Physics Contact Reports](https://docs.omniverse.nvidia.com/kit/docs/omni_physics/latest/extensions/runtime/source/omni.physx/docs/dev_guide/contact_reports.html)。資料只在回報步有效，本腳本於 callback 複製需要的數值。材質、形狀及 offset 可參考 [Colliders](https://docs.omniverse.nvidia.com/kit/docs/omni_physics/latest/dev_guide/rigid_bodies_articulations/collision.html)。

已做本機語法／作用域結構核對，尚未在 Isaac Sim 6.0.1-rc.7 實跑。如果此版本／GPU配置不提供預期接觸 callback，metadata 會記錄錯誤或 contact_reporting_ok=false，不能把這種情況當成無碰撞或驗收通過。
